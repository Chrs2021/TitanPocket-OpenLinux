# FS1860 speaker amplifier

`sound/soc/codecs/fs1860.c` — new ASoC codec driver for the FourSemi FS1860
smart amplifier on i2c3/0x34. Config: `CONFIG_SND_SOC_FS1860=y`.

It plugs into MediaTek's existing external-amp hook
(`sound/soc/mediatek/common_int/mtk-soc-speaker-amp.c`, entry
`MTK_SPK_FOURSEMI_FS1860`), which binds the `mediatek,speaker_amp` node and
makes the machine driver attach our DAI (`fs1860-aif`, codec name `fs1860`)
to the hostless `ext_Speaker_Multimedia` link (ALSA device 30,
`Speaker_PLayback`).

For how audio actually reaches the amp, see [../audio.md](../audio.md).

## Where the knowledge came from

On stock Android the kernel only exposes a raw I2C pass-through
(`/dev/smartpa_i2c`, Agold `fs16xx` misc driver). All programming lives in the
**unstripped** vendor library `/vendor/lib64/libfs1860.so` (+
`libfs16xx_interface.so`), which was disassembled (`reference/libfs1860.dis`,
`fs_more.dis`, `fs_calib.dis`). The steady-state configuration was then
**captured from the running phone** under Android with a read-only dump tool
(`userspace/src/android/fsdump.c`), both idle and while playing, and the
decoded preset mapping was checked against it (26 of 27 registers matched;
`0xA8` is adjusted at runtime).

## Register model

16-bit **big-endian** registers (use `i2c_smbus_*_word_swapped`). Closely
resembles NXP TFA98xx:

| Reg | Meaning |
|---|---|
| 0x00 | status; bit 1 = PLL locked to I2S clock (`0x005F` when running) |
| 0x03 | revision, `0x0703` |
| 0x04 | I2S control: [15:12] rate (8k=0, 16k=3, 32k=6, 44.1k=7, 48k=8), [4:3] channel (mono mix = `11`), [7:6] AEC output |
| 0x06 | volume in [15:8]; `0xFF` = HAL's normal level, 0.5 dB steps (assumed) |
| 0x09 | system control: bit 0 PWDN, bit 3 AMPE |
| 0x0B | access key: `0xCA91` unlocks protected registers, `0` locks |
| 0x62–0x69 | speaker-protection coefficients derived from the factory R25 (OTP) |
| 0x82 / 0x86 | DSP coefficient data / address |
| 0xA1 | mute/config (bit 12) |
| 0xA2 / 0xA6 | DSP RAM data / address |
| 0xAF | temperature protection: `0x362B` on, `0x7623` off |
| 0xBD | DSP status: `0x0803` idle, `0x5803` (or `0x3803`) processing audio |
| 0xC4 | power key: `0x000F` during operation |
| 0xE8 | OTP calibration word (behind unlock); this unit: `0x8011` |

## Init (once, on first stream)

1. `Fs16xx_reg_defaults` from the library (12 writes, includes unlock/lock).
2. Upload the preset `fs16xx_01s_mono.preset` (`request_firmware`, shipped in
   the ramdisk under `/lib/firmware` from the phone's own vendor partition):
   - file = 468-byte header (version `0x0703`) + 512 u16 coefficients
   - AMPE off, unlock, wait DSP idle
   - `0xA6 = 0`, then 81 words from header offset 144 to `0xA2` as
     `[b1, b0, 0, b2]` of each LE u32
   - `0x86 = 0`, then for i in 0..255: `0x86 = i` and a 4-byte write to
     `0x82` of `[hi(c[2i]), lo(c[2i]), hi(c[2i+1]), lo(c[2i+1])]`
   - lock, restore 0x09
3. Replay `fs1860_config[]` under the unlock key: the registers Android leaves
   programmed after init (preset selection for 44.1/48k, mono, volume/mute,
   protection, and 0x62–0x69 calibration).

> **Unit-specific values:** 0x62–0x69 depend on this phone's speaker
> calibration (OTP 0xE8). Another Titan Pocket needs its own capture, or an
> implementation of `fs16xx_update_coef_from_r25` (partially decoded in
> `reference/fs_calib.dis`).

## Speaker on / off

Triggered from the DAI: `prepare` and `digital_mute(0)` -> on,
`digital_mute(1)` (hw_free) -> off. The driver reads 0x09 to learn the real
state rather than trusting a flag.

**On:**
1. `0xC4 = 0x000F`
2. `0x09`: clear PWDN **and AMPE**
3. wait for PLL lock (status bit 1), up to 100 ms
4. wait DSP idle (`0xBD & 3 == 0`), up to 50 ms
5. set AMPE — **the DSP only starts on an AMPE rising edge while the I2S
   clock is present.** Leaving AMPE set from init produced a locked PLL but a
   silent DSP (`0xBD = 0x0803`) — the key bug during bring-up.
6. 5 ms soft-start, then `0xAF = 0x362B`

**Off:** `0xAF = 0x7623`, set PWDN, wait DSP idle, `0xC4 = 0`.

## hw_params

Writes the rate code into 0x04[15:12] and clears [7:6]. Supported: 8, 16, 32,
44.1, 48 kHz. The preset set index (0 = 44.1/48k, 1 = 16/32k) is fixed to 0 in
the replayed config; 16/32k streams would need the idx-1 values.

## Controls

`Speaker Amp Volume` (0–255, register 0x06 high byte). Default after init is
the HAL's 0xFF; the test script sets it explicitly.

## Debugging

```sh
i2cget -f -y 3 0x34 0x09 w     # SMBus is byte-swapped: 0x0800 means 0x0008
i2cget -f -y 3 0x34 0xbd w     # 0x0358 = 0x5803 -> DSP running
echo 'file fs1860.c +p' > /sys/kernel/debug/dynamic_debug/control  # if DYNAMIC_DEBUG
```
Remember BusyBox `i2cget` parses register numbers as hex even without `0x`.
